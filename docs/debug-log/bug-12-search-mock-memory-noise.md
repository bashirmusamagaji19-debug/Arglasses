# Bug 12：历史检索混入旧 mock 记忆

## 现象

搜索关键词 `鼠标` 时，结果中除了真实 VLM / OCR 产生的鼠标记录，还出现了一条旧 mock 记忆：

```text
问题：手上是什么
摘要：模拟场景摘要：本次交互模拟了 AI 眼镜看到当前场景...
OCR：模拟 OCR：画面中可能包含电脑屏幕、课程笔记、水杯...
```

从页面上看，这条记录和 `鼠标` 没有关系，影响演示观感。

## 排查过程

1. 检查 `LightweightSemanticSearchProvider`，确认当前检索不是 SQLite `LIKE`，而是读取最近记忆后做轻量排序。
2. 搜索结果页面原本只展示 `question` 和 `scene_summary`，没有展示 `answer`。
3. 旧 mock 记忆的 `answer` 字段可能包含 `鼠标`，但页面没有显示，所以看起来像是无关记录被召回。
4. 继续查看 provider，发现只要得分 `> 0` 就会返回，没有区分真实 AI 记录和早期 mock 记录。

## 根因

这是两个问题叠加：

- 搜索 UI 展示信息不足，只显示摘要，不显示回答，用户无法判断命中原因。
- 轻量语义检索没有过滤早期 mock 记录；当 mock 文本里包含关键词时，会和真实记录一起返回。

## 处理方案

1. 在搜索结果里增加 `answer` 展示，让命中原因更清楚。
2. 在 `LightweightSemanticSearchProvider` 中加入 mock 过滤：

```text
如果本次搜索已经有真实记录命中
-> 过滤带有“模拟 OCR / 模拟 VLM / 模拟场景摘要 / mock”标记的旧记录

如果只有 mock 记录命中
-> 仍然返回，避免纯 mock demo 阶段搜索为空
```

## 为什么不直接删除所有 mock 记录

项目早期 demo 仍可能运行在 mock OCR / mock VLM 模式。如果一刀切过滤 mock 记录，会导致纯 mock 模式下搜索结果为空。

所以当前规则是保守过滤：真实记录存在时，优先展示真实记录；只有 mock 记录可用时，仍保留结果。

## 面试复盘说法

> 我在测试历史检索时发现，真实 AI 记录和早期 mock 记录会混在一起，影响演示可信度。排查后发现并不是 SQLite 错误，而是轻量检索只按得分返回，同时 UI 没展示 answer，导致命中原因不透明。  
> 修复时我没有直接删除所有 mock 数据，因为项目仍支持 mock 模式。我做的是条件过滤：当真实记录已经命中时，过滤带 mock 标记的旧记录；如果系统只有 mock 记录，仍然允许返回。这样既提升真实 demo 的质量，又不破坏早期 mock 演示路径。
